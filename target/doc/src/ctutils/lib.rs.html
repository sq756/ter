31//! # API Design
32//!
33//! ## [`Choice`]: constant-time analogue for [`bool`]
34//! Values of this type are one of either [`Choice::FALSE`] or [`Choice::TRUE`].
35//!
36//! To achieve constant-time operation, `Choice` is ultimately used in combination with special
37//! CPU-specific constant-time predication instructions implemented by the [`cmov`] crate
38//! (with a portable "best effort" fallback that cannot provide guarantees).
39//!
40//! It additionally uses various methods to hint to the compiler that it should avoid inserting
41//! branches based on its value where it otherwise would if `bool` were used instead, but cannot
42//! provide guarantees in this regard.
43//!
44//! ## [`CtOption`]: constant-time analogue for [`Option`]
45//! The core `Option` type is typically great for representing the conditional absence or presence
46//! of a value, and provides a number of handy combinators for operating on them.
47//!
48//! However, it has a rather fundamental flaw when constant-time is desirable: its combinators are
49//! lazily evaluated. To ensure constant-time operation, all combinators must be eagerly evaluated
50//! so they aren't conditionally executed based on the value's presence.
51//!
52//! `CtOption` instead carries a `Choice` along with a value, which makes it possible to do
53//! something it isn't with `Option`: evaluate combinators eagerly instead of lazily, running the
54//! same functions regardless of the value's effective presence or absence.
55//!
56//! ## [`CtEq`]: constant-time analogue for [`PartialEq`]/[`Eq`]
57//! Equality testing often short circuits for performance reasons, but when comparing values in
58//! constant-time such short-circuiting is forbidden.
59//!
60//! The `CtEq` trait is a replacement for these scenarios. It's impl'd for several core types
61//! including unsigned and signed integers as well as slices and arrays. It returns a `Choice`
62//! as opposed to a `bool`], following the standard practice in this crate.
63//!
64//! *NOTE: for `subtle` users, this is the equivalent of the `ConstantTimeEq` trait*
65//!
66//! ## [`CtSelect`]: constant-time [predication]
67//! Predication in computer architecture describes methods for conditionally modifying state
68//! using non-branch instructions which perform conditional modifications based on a *predicate*
69//! or boolean value, in the design of this library a `Choice`.
70//!
71//! The `CtSelect` trait provides methods for performing conditional moves, either conditionally
72//! modifying a value in-place, or selecting from two different inputs and returning a new one.
73//!
74//! *NOTE: for `subtle` users, this is the equivalent of the `ConditionallySelectable` trait*
75//!
76//! [predication]: https://en.wikipedia.org/wiki/Predication_(computer_architecture)
77//!
78//! # [`subtle`] interop
79//!
80//! When the `subtle` feature of this crate is enabled, bidirectional [`From`] impls are available
81//! for the following types:
82//!
83//! - [`Choice`] <=> [`subtle::Choice`]
84//! - [`CtOption`] <=> [`subtle::CtOption`]
85//!
86//! This makes it possible to use `ctutils` in a codebase where other dependencies are using
87//! `subtle`.
